01

先看懂原理：为什么这套方案不容易封号？

Claude（Anthropic）风控看的不只是“能不能连上”，而是出口 IP 干净度 + 关联风控域名同出口 + 浏览器语言/时区一致 + 无 WebRTC/IPv6 泄漏。下面这张图就是你的流量完整走向：

🔗 为什么要“两跳”？

直连海外静态家宽往往丢包高、延迟炸；把三网优化VPS作为前置中转（dialer-proxy），既稳又快，而 Claude 只看得到最终的干净家宽 IP。

🎯 为什么规则要置顶？

把 Claude 主站以及 hcaptcha、cloudflare、stripe、sentry、appleid 全部锁在同一个家宽出口，杜绝风控 IP 不一致。

🧯 为什么需要启动熔断？

双击「打开 Claude」时先请求 ipinfo.io，只要出口不是你设定的家宽 IP，立即弹窗阻止，绝不会误用国内或机房 IP 登号。

常见问题与排障解答（FAQ）

        

        
遇到报错或不确定某个细节？先按关键词搜索，或按分类筛选查看解决方案：


        

          
          

            
            
            
            
            
          

        


        

          

            
              家宽选型IPRoyal 里 ISP 和 Residential 有什么区别？不小心买成 Residential 能用吗？
              ▼
            
            

              
不能混用，务必买左侧菜单的 ISP（Static Residential）：

              
    
                
  • ISP（静态住宅）：按颗买断周期（约 $2.4～$4/月），给你一个固定不变的独享住宅 IP 且不限流量，适合长期固定登录同一个 Claude 账号。
    • 
                
  • Residential（动态住宅）：按 GB 卖流量（约 $7/GB），底层是不断轮换的家宽池，不仅对话传附件烧钱，而且一旦 IP 跳变，桌面「打开 Claude」的固定 IP 校验会立刻报错拦截。
    • 
              

            

          


          

            
              家宽选型刚买下来的 IPRoyal 静态 IP 怎么看干不干净？怎么续费才不会换 IP？
              ▼
            
            

              
怎么验纯度：配好代理后，在未登录 Claude 前先用 Chrome Clean (US) 打开 https://ping0.cc 和 https://scamalytics.com。理想状态是：IP 类型显示 家庭宽带 / ISP（双 ISP），Scamalytics 欺诈分（Fraud Score）尽量低（绿色/低风险）。如果一开出来就是极高风险红标，说明前任租户刚拿它干过坏事，直接联系 IPRoyal 右下角在线客服要求换一个干净 IP。

              
怎么保住原 IP：IPRoyal 的静态 ISP 只要在到期前续费（Extend）或开启自动续费（Auto-extend），原 IP、端口和账号密码都会保持不变；一旦彻底过期释放就找不回来了。

            

          

          

            
              原理与风控为什么一定要“三网优化VPS 中转 + 家宽落地”两跳？只用中转或只用家宽不行吗？
              ▼
            
            

              
只用三网优化VPS（机房 IP）：机房线路属于数据中心 ASN，极容易被 Anthropic / Cloudflare 标记为机房代理，轻则频繁跳人机验证，重则注册/绑卡或日常对话中直接封号。

              
国内直连家宽：海外静态住宅代理服务器通常不针对中国大陆优化，直连高丢包、握手慢甚至直接被墙阻断。

              
两跳链式代理（三网优化VPS → 家宽）：用三网优化VPS的优质回国/出国专线保证低延迟和加密稳定性，最后由干净的独享静态住宅 IP 访问 Claude，兼顾速度与低风控。

            

          


          

            
              原理与风控几个人共用同一个三网优化VPS面板下发的不同订阅，会互相连坐封号吗？
              ▼
            
            

              
不会。三网优化VPS只是加密运输通道，Claude 服务端完全看不到第一跳的中转 IP，它只能看到你们各自购买的第二跳 独享静态住宅 IP。

              
只要满足：每人各自买独立家宽 IP + 各自独立 Claude 账号与支付方式 + 各自独立浏览器目录，就不会因为共用同一台中转服务器而被关联。唯一需要注意的只是大家约定好不要拿中转线路挂 BT 或下载大文件，避免把中转带宽或月流量耗尽。

            

          


          

            
              原理与风控平时刷 B 站、看 YouTube、下大文件，会不会消耗昂贵的家宽流量？
              ▼
            
            

              
完全不会。因为 mihomo-override.js 故意没有把 IPRoyal-US 塞进任何「自动选择」或「手动切换」策略组，只有被置顶规则精确命中的那 20 多个域名（Claude 主站、人机验证、风控遥测、Stripe 支付、Apple 登录和 ipinfo.io）才会走家宽。

              
其余国内网站照常直连，普通外网（如 GitHub、Google、YouTube）照常走三网优化VPS，一滴家宽流量都不会浪费。

            

          


          

            
              报错排查双击「打开 Claude」弹窗提示“代理出口不符合预期”怎么办？
              ▼
            
            

              
这是脚本的熔断保护生效了（它成功帮你挡住了一次异常 IP 登号风险）。请按以下 4 步排查：

              
    
                
  • 看弹窗里的「当前出口」IP 是什么：如果是国内 IP → 说明代理客户端没开「系统代理」；如果是中转机房 IP → 说明客户端选成了「全局模式 (Global)」或 JS 覆写没生效。
    • 
                
  • 检查客户端「规则」页面：最顶部是否能看到 DOMAIN,ipinfo.io,IPRoyal-US？如果看不到，说明 JS 覆写没有保存或未在当前订阅启用。
    • 
                
  • 检查家宽是否可用：在客户端「连接/日志」里查看连向 IPRoyal-US 的报错，确认家宽的 IP、端口、用户名、密码没填错且没有到期。
    • 
                
  • 核对 config.psd1：确认 %LOCALAPPDATA%\ClaudeCleanLauncher\config.psd1 里的 ExpectedExitIp 填的是最新家宽 IP。
    • 
              

            

          


          

            
              报错排查前置节点名为什么推荐留空？如果订阅里有多个节点会自动选哪一个？
              ▼
            
            

              
留空时，覆写脚本不会暴露任何节点名称，也不用把订阅链接硬编码进脚本文本里（更隐秘、更安全），而是直接在客户端内存中扫描你当前激活的订阅，自动优先选择第一个 IPv4 的 TCP 节点（自动跳过 HY2、TUIC 和 IPv6 节点）。

              
如果你的订阅里有多条不同线路、且希望固定走其中某一条，再在生成器里的「前置中转节点名（可选）」中填入该节点的准确名称即可。

            

          


          

            
              报错排查运行 .ps1 时闪退，或提示“在此系统上禁止运行脚本”怎么办？
              ▼
            
            

              
Windows 默认禁止直接双击或无参数运行本地 .ps1 脚本。请务必使用带绕过参数的命令启动（桌面快捷方式已经自动写好了这个参数，无需担心）：

              
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install-Shortcuts.ps1

              
另外，如果从网上下载的压缩包解压后被 Windows 标了“来自其他计算机”锁定，可以右键 .zip 文件 → 属性 → 勾选右下角「解除锁定」→ 确定后再解压。

            

          


          

            
              报错排查点击「打开 Claude」提示“未找到 Chrome Clean (US) 配置目录 / 缺少 Local State”？
              ▼
            
            

              
为了防止误启动你平时用来上国内网站的默认 Chrome 造成环境污染，Start-Claude.ps1 会强制检查隔离目录是否已经初始化完毕。

              
只需运行一次 powershell -NoProfile -ExecutionPolicy Bypass -File .\Init-ChromeClean.ps1，等空白英文 Chrome 弹出来之后正常点右上角关闭，它就会自动生成 Local State 和 Default\Preferences。

            

          


          

            
              原理与风控为什么必须改 Windows 系统时区？用完不改回去有什么影响？
              ▼
            
            

              
网页可以通过 JavaScript 的 Intl.DateTimeFormat().resolvedOptions().timeZone 直接读取操作系统时区。如果你的出口 IP 在美国洛杉矶（UTC-8），浏览器上报的时区却是 Asia/Shanghai（UTC+8），属于非常典型的“代理特征不匹配”。

              
因为修改的是 Windows 全局系统时区，可能会影响战网客户端、部分对本地时间敏感的游戏或日历提醒，所以用完 Claude 后记得点一下桌面「恢复北京时间」（该脚本固定恢复为 China Standard Time，即使你中途多次点了「打开 Claude」也不会出错）。

            

          


          

            
              日常与维护我买到的 IPRoyal 静态 IP 不在洛杉矶（比如纽约、达拉斯、芝加哥）怎么改？
              ▼
            
            

              
完全没问题！只要保证 Windows 目标时区与你 IP 所在城市属于同一时区即可。在本页第 04 节「在线生成器」的地区下拉框里直接选择对应美国区域，或者手动把 config.psd1 中的 TargetTzId 改为：

              
    
                
  • 美西（洛杉矶 / 旧金山 / 西雅图）：Pacific Standard Time
    • 
                
  • 山地（丹佛 / 盐湖城）：Mountain Standard Time
    • 
                
  • 美中（芝加哥 / 达拉斯 / 休斯顿）：Central Standard Time
    • 
                
  • 美东（纽约 / 弗吉尼亚 / 迈阿密）：Eastern Standard Time
    • 
              

            

          


          

            
              原理与风控为什么建议只开「系统代理」而不是开 TUN 模式？为什么要关闭 QUIC 嗅探？
              ▼
            
            

              
关于系统代理：Chrome 和 PowerShell 走 HTTP 系统代理时，所有 HTTPS 请求都会以 TCP HTTP CONNECT（携带原始域名） 直接发给本机 Mihomo，既不会经过本机 DNS 也不会走运营商 IPv6（2409:）直连，链路最干净、最不易泄漏。

              
关于关闭 QUIC 嗅探：IPRoyal 静态住宅 HTTP 代理不支持 UDP 转发（配置里是 udp: false）。关闭 sniffer.sniff.quic 可以防止 UDP 443（HTTP/3）流量在嗅探匹配到纯 HTTP 家宽时出现卡顿或异常回退。

            

          


          

            
              日常与维护以后家宽到期换了新 IP，或者修改了密码，需要改哪几个地方？
              ▼
            
            

              
只需要同步更新 2 个地方（建议回到本页第 04 节重新生成一遍最省心）：

              
    
                
  1. 代理客户端里的 全局 JS 覆写（mihomo-override.js）：更新 ISP_SERVER / 端口 / 用户名 / 密码并刷新订阅；
    2. 
                
  2. 本机 %LOCALAPPDATA%\ClaudeCleanLauncher\config.psd1：更新 ExpectedExitIp（若跨州换了城市，一并更新 TargetTzId）。
    3. 
              

            

          


          

            
              日常与维护已经打开一个 Claude 窗口了，再点一次「打开 Claude」会出问题吗？
              ▼
            
            

              
不会，可以放心重复点击。脚本检测到当前已经是目标美国时区时会直接跳过切换步骤，不会弹窗重复要 UAC 权限，也不会关闭你现有的普通 Chrome 或已打开的 Claude 标签页，只会在同一个 Chrome Clean (US) 里新开一个 claude.ai 标签页。
